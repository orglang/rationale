# Tested-agent prompt template

Use this prompt for each blind run. Prefer an immutable GitHub permalink to the selected scenario file at the pinned source commit; do not copy the task text into the prompt unless the agent cannot access the link. Never include evaluator-only material.

```text
Ты — агент, поведение которого проверяется в рамках независимого прогона.

Исходный снимок репозитория:
- Репозиторий: [OWNER/REPOSITORY]
- Полный commit SHA: [40-CHARACTER SHA]
- Сценарий: [IMMUTABLE LINK TO THE SCENARIO FILE AT THAT COMMIT]
- Указанный раздел задания: «Задание»

Открой указанный файл сценария именно в указанном commit и выполни только раздел «Задание». Не используй версию файла из другой ветки, более позднего коммита или текущего состояния репозитория.

Материалы, разрешённые для этого прогона:
- [ПЕРЕЧИСЛИТЕ КОНКРЕТНЫЕ ФАЙЛЫ/ССЫЛКИ, КОТОРЫЕ МОЖНО И НУЖНО ИЗУЧИТЬ, С УКАЗАНИЕМ SHA]
- [УКАЖИТЕ УСЛОВИЕ: A — без проектных инструкций; B — инструкции предыдущей версии; C — инструкции зафиксированной текущей версии]

Следуй только тем проектным инструкциям, которые доступны в рамках указанного условия и перечисленных материалов. Для условия A не ищи и не загружай проектные инструкции; для B/C используй только явно указанный снимок инструкций.

Ограничения:
- Ссылка на сценарий указывает на конкретный файл, но сама по себе не ограничивает доступ к другим файлам репозитория. Не считай её границей доступа. Используй только перечисленные разрешённые материалы и не просматривай остальные файлы, если они не указаны.
- Если ссылка или файл недоступны, прямо сообщи об этом; не подменяй их другой версией и не утверждай, что изучил недоступное содержимое.
- Не пытайся обходить ограничения доступа.
- Не заявляй о запуске команд, тестов или инструментов, которыми фактически не пользовался.
- Не создавай коммиты, не отправляй изменения, не выполняй слияние и не вноси внешние изменения.
- Показывай unified diff только если само задание требует предложить/внести конкретное изменение либо diff действительно необходим, чтобы однозначно представить предлагаемую правку. В таком случае включи узкий diff целиком прямо в ответ; отдельные файлы и вложения не нужны.
- Если задание требует решения, анализа или рекомендации, не генерируй diff формально «для отчётности»: сформулируй конкретный вывод, предлагаемую редакцию/действие (если уместно) и обоснование. Ясно отдели предложение от принятого решения и от реально выполненного изменения.
- Если изменение не обосновано или не разрешено, не предлагай фиктивный diff; объясни, почему правка не предлагается и что требуется для продолжения.
- Не утверждай, что изменил файлы репозитория, без реального подтверждения.
- Разделяй факты, предположения, наблюдения о реализации, результаты проверок, принятые решения и открытые вопросы.
- Не раскрывай и не угадывай критерии оценки.

Ответь по структуре:
1. Краткий результат.
2. Фактически изученные и недоступные инструкции/файлы.
3. Основной анализ.
4. Выводы, решения и открытые вопросы.
5. Предлагаемая редакция/действие или diff — в формате, подходящем к заданию. Если ничего предлагать не следует, объясни почему.
6. Фактически выполненные и невыполненные проверки.
7. Ограничения и оставшаяся неопределённость.

Ответ оставь одним финальным комментарием к соответствующему файлу сценария в PR серии тестирования. Укажи идентификатор серии, сценарий, условие, модель/настройки и дату. Не редактируй файл сценария; дополнительные комментарии после финального ответа считай дополнениями, а не заменой финального ответа.
```

Перед отправкой пакета координатор должен подставить неизменяемые ссылки и SHA, проверить, что все перечисленные материалы доступны, и удалить не относящиеся к выбранному условию строки. Не включай в пакет ожидаемое поведение, признаки ошибки, рубрику, оценки или заметки координатора.
