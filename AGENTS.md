# Agent instructions

## Research documentation

- Read [`CODING_STANDARDS.md`](CODING_STANDARDS.md) before editing or reviewing research documentation.
- Use it for recurring editorial criteria, especially semantic accuracy, evidence boundaries, canonical explanations, and final review.
- Prefer direct, affirmative descriptions of a section's purpose, scope, behavior, and ownership. Avoid rhetorical negative contrasts such as "X, not Y", "not X but Y", "rather than", and "instead of" when the intended meaning can be stated directly.
- When topics belong in different sections or documents, say where each topic is covered and link to the canonical location. For example, replace "This section covers pool selection, not transaction types" with "This section describes pool selection. Transaction types are described in [the transaction-type section](path/to/section)."
- Keep negative statements when they express a meaningful constraint, prohibition, verified absence, likely-misinterpretation guard, or genuine uncertainty. Do not remove a necessary caveat or turn an unverified claim into a fact merely to make the prose affirmative. State each caveat once.
- Check the relevant document and directory for task-specific context before making changes.
- Avoid editorial process commentary, vague authority claims, and boilerplate qualifications. Each sentence should contribute a technical fact, an attributed claim, evidence, a limitation, an unresolved question, or a useful cross-reference. Delete sentences that only describe editing history or state that evidence is required without naming what would establish the claim. When a claim remains unsettled, mark it Open and identify the concrete source or test that could resolve it.
